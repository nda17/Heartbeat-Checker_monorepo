# Heartbeat Checker для Android

Небольшое Android-приложение открывает актуальный кабинет `https://heartbeat-checker.ru/app` в Trusted Web Activity. При отсутствии TWA используется Custom Tab; WebView, JavaScript bridge, локальной копии сайта, собственных cookies и native OAuth нет. Единственный доверенный origin — `https://heartbeat-checker.ru`; внешние страницы и OAuth остаются под управлением браузера. Пароли, сессии и cookies приложение не читает. Пользователь может управлять браузерными данными в самом браузере.

Android 10+ (`minSdk 29`), пакет `ru.heartbeatchecker.app`, `versionName 1.1.1`, `versionCode 3`. App Links ограничены точными `/app`, `/app/settings`, `/app/billing`, `/app/admin`; для `/app` разрешена существующая пара UUID `monitor`+`incident`. Login, подтверждение email, сброс пароля и OAuth callback не перехватываются. Любые другие входящие URL, query и fragment отклоняются. Навигацией внутри TWA и возвратом с внешних страниц управляет браузер.

Отдельная Activity подключения уведомлений принимает только `/android/push/connect` и `/android/push/complete` этого origin без query/fragment. Возврат из браузера передаёт `pairingId`, одноразовый `completionCode` и `clientState` как String extras целевого Android intent; приложение сверяет их с локальным запросом. Старый ID-only callback отклоняется.

## Запуск кабинета

Нажатие значка приложения открывает кабинет через автоматическое подключение уведомлений к текущей браузерной сессии. Ожидание bootstrap ограничено восемью секундами; ошибка не блокирует кабинет. После передачи управления браузеру native Activity завершается; Back не открывает отдельное меню приложения. Completion callback подтверждает только передачу intent, а не загрузку страницы. Сетевые ошибки и навигацию в открытом кабинете обрабатывает браузер.

После пересоздания незавершённый запуск выполняется один раз заново. Подтверждённая ошибка до передачи управления сохраняется как экран с явными кнопками «Повторить» и «Закрыть»; автоматических повторов нет. Для повтора создаётся новый TwaLauncher. Разрешённые App Links проходят прежнюю проверку origin/path/query. Share intents, старый ярлык черновиков и другие неизвестные actions завершаются без чтения переданного содержимого.

Локальные черновики и перенос адреса в web-форму удалены. Файлы, оставшиеся от версии 1.0.0, новая версия не читает, не изменяет и не отправляет; удалить их можно через очистку данных приложения в настройках Android или удаление приложения. Новых миграций и очистки данных при обновлении нет.

## Уведомления на устройстве

Используется только RuStore Push SDK 7.5.0; FCM в эту сборку не входит. При запуске APK создаётся запрос подключения сроком на пять минут. После входа браузер получает одноразовый код и возвращает его текущей установке; приложение проверяет локальный state, запрашивает разрешение Android и получает SDK-токен. Сравнивать коды и выбирать телефон не нужно. Если браузер требует жест пользователя для возврата, доступна кнопка «Вернуться в приложение». Проверочный PKCE verifier, state, код завершения и отдельные учётные данные устройства хранятся зашифрованными ключом Android Keystore в каталоге без резервного копирования. Cookies браузера приложение не получает.

Первая успешная привязка с разрешением включает Push по умолчанию для текущих и будущих мониторов. Переключатель монитора действует на все подключённые телефоны; сохранённое выключение не сбрасывается. После отказа в разрешении приложение не запрашивает его при каждом запуске. Локальное или серверное отключение устройства требует явного включения через настройки этого телефона.

После проверенного возврата из браузера подключение выполняет WorkManager. Переход в кабинет через восемь секунд и закрытие native Activity не отменяют подтверждённую привязку. Данные подтверждения остаются в зашифрованном хранилище; в очереди находится только идентификатор операции. При следующем запуске приложение возобновляет незавершённую операцию в пределах трёх попыток. Одноразовый exchange отправляется не более одного раза: при потере ответа выполняется только чтение серверного состояния, в том числе после истечения срока самого подтверждения. Неподтверждённый браузером запрос автоматически не завершается.

SDK получает только идентификаторы доставки, устройства и поколения подключения со сроком действия. Текст события приложение запрашивает отдельно через HTTPS с учётными данными устройства; перенаправления запрещены. Перед показом повторно проверяются подключение, разрешение и срок действия. Уведомления скрывают содержание на заблокированном экране. Нажатие открывает проверенный адрес инцидента; доступ к нему снова проверяет сайт. Сохранённые идентификаторы и порядковые номера подавляют дубликаты и запоздалое сообщение о сбое после восстановления. Тексты событий офлайн не сохраняются.

В настройках уведомлений этого телефона видны последняя ошибка RuStore и последний этап обработки push с временем. Сохраняются только фиксированные коды состояния, без текста исключений SDK, токенов и содержимого событий. «Передано Android» означает вызов системного показа, а не подтверждение видимости в шторке. Отсутствие записи не доказывает, что сообщение не приходило. RuStore должен иметь возможность работать в фоне; ограничения могут задерживать доставку. Аккаунт RuStore не определяет получателя: телефон привязывается к текущему аккаунту Heartbeat Checker.

Отключение сразу запрещает локальный показ и отменяет работу доставки; отзыв подключения на сервере получает до трёх автоматических попыток. При сетевой ошибке зашифрованные данные для отзыва сохраняются. Явное повторное подключение повторяет отзыв и не создаёт новую привязку, пока прежняя не отозвана. Транспортный SDK-токен сохраняется, чтобы отложенное удаление не нарушило повторное подключение; без нового подтверждения аккаунта сообщения не показываются. При истечении сессии повторное подключение выполняется при следующем запуске APK. Выход или смена аккаунта внутри уже открытой TWA прекращает доступ старой привязки, но для нового подключения нужен следующий запуск APK либо кнопка в настройках. Обновление SDK-токена не продлевает сессию и не создаёт новое подключение. Доставка зависит от сети, разрешений Android и доступности RuStore; кабинет работает и без уведомлений.

## Сборка

Нужны JDK 17, SDK API 37.0 и Build Tools 36.0.0. Wrapper фиксирует Gradle 9.6.0 с SHA256, AGP — 9.4.0, android-browser-helper — 2.7.3. Нативных библиотек JNI нет.

```sh
sdkmanager 'platforms;android-37.0' 'build-tools;36.0.0'
./gradlew --no-daemon :app:lint :app:testDebugUnitTest :app:assembleDebug
```

SDK задаётся через `ANDROID_HOME` или ignored `local.properties`. Локальные инструменты и временные артефакты можно держать в `.local/`; ключи и APK не добавляются в Git.

Release требует существующий защищённый keystore и четыре переменные:

- `ANDROID_KEYSTORE_FILE` — абсолютный путь к файлу;
- `ANDROID_KEYSTORE_PASSWORD`;
- `ANDROID_KEY_ALIAS`;
- `ANDROID_KEY_PASSWORD`.

Для обоих паролей можно вместо значения передать путь через суффикс `_FILE`. CI получает keystore из защищённого секрета `ANDROID_KEYSTORE_BASE64` и создаёт временный файл. Ключ не генерируется автоматически. Без полной конфигурации упаковка release завершается отказом.

Также необходим публичный `RUSTORE_PUSH_PROJECT_ID` зарегистрированного проекта с тем же пакетом и сертификатом. Workflow получает его из repository variable. Серверный сервисный ключ RuStore в APK, Gradle и Android workflow не передаётся. Debug/CI могут собираться без project ID: кабинет доступен, но такая сборка не подтверждает работу RuStore Push. SDK использует явный logger без записи токенов, сообщений и ошибок провайдера в logcat.

```sh
./gradlew --no-daemon :app:assembleRelease
```

APK: `app/build/outputs/apk/release/app-release.apk`. До публикации обязательны `apksigner verify --verbose --print-certs`, проверка package/version/SDK/permissions и сверка SHA256 сертификата с Digital Asset Links на сайте. Без правильного DAL браузер показывает Custom Tab с адресом; это не подтверждённая TWA. Ключ подписи необходимо сохранить для всех обновлений, а `versionCode` увеличивать при каждом новом APK.

## Приёмка на устройстве

Сборка и unit-тесты не заменяют проверку на Android. Для release проверить install/update, TWA с фактической подписью и Custom Tabs fallback, вход и OAuth в браузере, возврат/Back, точные App Links и отказ callbacks, холодный/повторный запуск, пересоздание Activity до передачи управления и после ошибки, ручной повтор при отсутствии браузера, TalkBack/масштаб текста и ручное создание монитора в кабинете. Публикация и одобрение RuStore выполняются отдельно; наличие APK само по себе не означает приёмку магазина.

На подписанном APK отдельно проверить автоматическое подключение с физического телефона и возврат из кабинета, fallback «Вернуться в приложение», уведомления в foreground/background, отказ разрешения и отсутствие дистрибутора RuStore, последовательность DOWN/UP и повторы, переход по уведомлению, отключение, logout/истечение сессии и переподключение. Проверить сохранение opt-out при новом запуске и подключении второго устройства, светлую/тёмную темы, узкий экран и крупный шрифт локальных настроек. CI без production project ID и синтетический instrumentation smoke не заменяют эти проверки.

Для входа проверить email/пароль, новую регистрацию, VK и Яндекс: успешный вход, отмену, повтор, восстановление страницы из истории и Back после выхода. Веб-формы заменяют текущую запись истории и повторно проверяют сессию при восстановлении; это не гарантирует удаления всех внешних страниц провайдера из истории браузера. Задержка получения SDK-токена более восьми секунд не должна терять подтверждённое подключение. Проверка на втором телефоне требует нового события после его подключения, а не ранее отправленного инцидента.

Отправка в RuStore отложена до ручных тестов владельца и его отдельного указания на модерацию.
