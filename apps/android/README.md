# Heartbeat Checker для Android

Версия 2.3.3 (`versionCode 15`) — приложение React Native с нативной публичной страницей сервиса, помощью, экранами входа, регистрации, восстановления доступа, мониторов, уведомлений, оплаты и аккаунта. Публичная страница встроена в приложение; сайт в WebView не используется. Пакет `ru.heartbeatchecker.app` и ключ подписи должны остаться прежними, чтобы APK обновлял установленную версию 1.2.0. Успешная сборка сама по себе не доказывает совместимость обновления; её проверяют на подписанном кандидате и установленном старом APK.

Приложение работает на Android 10+ (`minSdk 29`). Сессии, OAuth PKCE и незавершённые платёжные намерения хранятся через Android Keystore и не попадают в браузерные cookies. Встроенный WebView используется только для Cloudflare Turnstile: веб-маршрут `/mobile/challenge` не содержит полей входа. Внешний OAuth открывается в Custom Tab; сервер возвращает короткий код через проверенный App Link, а обмен выполняет приложение. App Links для восстановления пароля, подтверждения OAuth-регистрации, возврата от оплаты и инцидентов проверяются по origin, пути и параметрам. Чужой заказ или монитор повторно проверяет API текущего аккаунта.

Оплата картой использует встроенную форму YooKassa, только если сервер и локальная сборка сообщают совпадающие магазин и режим. Иначе новый заказ идёт через существующую hosted-форму. После создания заказа адаптер не меняется. Idempotency key и параметры выбора сохраняются до POST; после перезапуска приложение сначала читает статус заказа. Токен платёжной формы существует только в памяти. Успех показывается лишь после серверного подтверждения платежа и начисления. Незавершённый заказ блокирует создание другого. Сайт продолжает использовать hosted-оплату.

Push-подключение выполняется для текущей Android-сессии с разрешения пользователя. Среди настроенных доступных транспортов, разрешённых сервером, приложение предпочитает FCM, затем Huawei HMS и только затем RuStore; правило применяется и к существующим установкам. Переход выполняется после успешного получения токена нового транспорта, при ошибке сохраняется прежний маршрут. Поздние callbacks не меняют завершённую или отозванную привязку. Текст инцидента приложение запрашивает у API после получения минимального сигнала; содержимое не помещается в push payload. Выход и истечение сессии блокируют показ и запускают защищённый отзыв привязки. Работу всех настроенных транспортов, переподключение, подавление дублей и переход по уведомлению нужно проверить на физических устройствах; CI их доставку не подтверждает.

## Сборка

Нужны Node.js 24.21.0, JDK 17, Android SDK API 37.0, Build Tools 36.0.0, NDK 27.1.12297006 и CMake 3.30.5. Gradle wrapper и npm lockfile фиксируют версии инструментов и зависимостей. SDK задаётся через `ANDROID_HOME` или игнорируемый `local.properties`.

```sh
cd apps/mobile && npm ci --no-audit --no-fund && npm run typecheck
cd ../android && ./gradlew --no-daemon :app:lint :app:testCiUnitTest :app:assembleCi
```

`assembleCi` создаёт release-like APK с встроенным JS bundle и debug-подписью, без production credentials и Metro. Эмуляторный CI использует `:app:connectedCiAndroidTest`. Debug-вариант тоже включает JS bundle, но CI проверяет именно release-like сборку.

### Отдельная dev-сборка по Wi-Fi

`Build or publish Android Dev` собирает `ru.heartbeatchecker.app.dev` с именем **Heartbeat Checker Dev** и отдельной постоянной подписью. Этот APK устанавливается рядом с обычным приложением, не обновляет его и не делит с ним Android Keystore или данные. Dev-сборка получает JavaScript с Metro: в ней нет встроенного JS bundle, а Fast Refresh меняет только JS/TS-код. Изменения Java, ресурсов или Gradle требуют нового APK. Production API и CAPTCHA остаются на HTTPS; HTTP разрешён только в отдельном dev-пакете для выбранного вручную локального Metro-сервера.

Доступ к APK на сайте требует входа администратора и MFA. Для создания кандидата workflow принимает полный SHA в `master` с успешным CI того же SHA; публикация запускается отдельно с `publish=true` и `candidate_run_id` уже проверенной сборки. Подпись берётся только из `ANDROID_DEV_KEYSTORE_*`, а ожидаемый публичный отпечаток — из `ANDROID_DEV_SIGNING_CERTIFICATE_SHA256`. Production-ключ подписи, Push и YooKassa-конфигурация в dev workflow не передаются. Dev-сборка не принимает production App Links; социальный вход, восстановление пароля, Push и любые действия по оплате в ней отключены. Вход и регистрация по email остаются доступны.

После установки APK с сайта запустите Metro на Mac из каталога `apps/mobile` командой `npm start -- --host 0.0.0.0`. Телефон и Mac должны быть в одной Wi-Fi-сети, а порт 8081 — доступен с телефона. На Android 17+ разрешите dev-приложению доступ к локальной сети при первом запуске: React Native запрашивает его до подключения к Metro. В dev-приложении встряхните телефон, откройте **Dev Menu → Change Bundle Location**, введите локальный IP Mac и порт без `http://`, например `192.168.1.20:8081`, затем нажмите **Apply Changes** — приложение автоматически перезагрузится; включите **Fast Refresh**. USB и `adb reverse` для этого не требуются. При смене IP Mac обновите адрес через Change Bundle Location; значение хранится отдельно внутри dev-пакета. Metro отдаёт исходный JS всем устройствам, которым открыт порт 8081, поэтому оставляйте его только в доверенной локальной сети.

Release собирается `:app:assembleRelease` с исходным защищённым keystore и переменными `ANDROID_KEYSTORE_FILE`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. Для паролей допустим путь через суффикс `_FILE`. Release требует публичные параметры `RUSTORE_PUSH_PROJECT_ID`, `FIREBASE_APP_ID`, `FIREBASE_PROJECT_ID`, `FIREBASE_API_KEY`, `FIREBASE_SENDER_ID`. Приватные серверные ключи в APK не передаются. Публичные `YOOKASSA_SDK_CLIENT_KEY` и `YOOKASSA_SHOP_ID` включают форму SDK только при соответствующей серверной настройке; без них остаётся hosted-оплата.

Отдельный `:app:assembleSdkTest` создаёт изолированный пакет `ru.heartbeatchecker.app.sdktest` с debug-подписью и обязательными публичными `YOOKASSA_SDK_TEST_CLIENT_KEY` и `YOOKASSA_SDK_TEST_SHOP_ID`. Его API направлен на `127.0.0.1:18080` через `adb reverse`; он не переключает production-магазин или сессию основного приложения.

Workflow `Build or publish Android` по умолчанию только собирает подписанный APK кандидата из полного SHA в master с успешным CI того же SHA, проверяет подпись, package/version, checksum и сохраняет неизменяемые GitHub artifacts. Он не публикует APK на сайте. Отдельный запуск с `publish=true` и `candidate_run_id` берёт точный принятый artifact и повторно проверяет SHA, ancestry, CI и подпись перед защищённой публикацией. Новый `release.json` для сайта продвигается отдельно после приёмки; текущая публичная версия остаётся 1.2.0 до этого шага. Отправка на модерацию RuStore этим workflow не выполняется.

## Приёмка кандидата

На физическом устройстве проверить обновление прежнего подписанного APK без потери идентичности, холодный запуск и вход, регистрацию с кодом, сброс пароля, OAuth Яндекс/VK и возврат из браузера. Отдельно проверить App Links, Back, крупный шрифт, светлую и тёмную темы, создание и редактирование монитора, часовой пояс, историю и уведомления. Для оплаты нужны реальные sandbox-сценарии SDK: завершение, отмена, неизвестный результат, возврат из подтверждения банка, повтор после потери сети и перезапуска. Проверить серверное начисление, отсутствие дублей и hosted fallback при отключённой конфигурации. Результат сборки, unit-тесты и HTTP smoke не заменяют эту приёмку.

Публикация на сайте и модерация RuStore — отдельные действия после ручной приёмки владельцем.
